# Kafka 面试题集：从六个问题收口

> 属于 S3 Kafka 深入 · 收口篇
> 上一篇：[可靠性与积压](./可靠性与积压)

Kafka 的高频问题，每题练到连续追问三层不卡壳。

## Q1：Kafka 为什么吞吐高？

三根支柱：**顺序写**（追加写是顺序 IO，磁盘顺序写接近内存）、**零拷贝**（sendfile，数据不经过用户空间）、**页缓存**（读写走内存）。加上分区提供并行度。

**追问：零拷贝怎么实现？** sendfile，磁盘 → 内核 → 网卡，跳过用户空间。

## Q2：如何保证消息不丢？

三段设防：生产端 `acks=-1 + retries + min.insync.replicas>=2`；Broker 端副本>=3 + unclean=false；消费端手动提交、先处理后提交。

**追问：acks=-1 就绝对不丢吗？** 不是，ISR 只剩 Leader 时会退化成 1，需配 min.insync.replicas>=2。

## Q3：如何保证不重复消费？

靠消费端幂等消化：唯一键、去重表、状态机。exactly-once 靠幂等生产者 + 事务 + 消费幂等。

**追问：为什么有重复？** at-least-once 语义 + 重试/崩溃。

## Q4：如何保证顺序？

Kafka 只保证单分区有序。同 key 哈希进同一分区 + 分区级串行消费。

**追问：要全局有序怎么办？** 单分区，但牺牲并行吞吐。

## Q5：rebalance 是什么，有什么危害？

消费组内成员/分区变化时重新分配分区的过程。危害是期间组内所有消费者停止消费（STW）。触发：实例加入退出、分区变化、处理超时被踢。

**追问：怎么减少？** 调大 max.poll.interval、静态成员、保持实例稳定。

## Q6：消息积压怎么处理？

看 lag 定位 → 扩容消费者（上限=分区数）→ 优化消费逻辑 → 极端用临时 topic 转储并行消化。

**追问：消费者扩容上限为什么是分区数？** 一个分区只能被组内一个消费者消费，实例多了会空闲。
