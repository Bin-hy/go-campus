# Go 微服务面试题集：从六个问题收口

> 属于 S4 Go 微服务 · 收口篇
> 上一篇：[治理与稳定性](./治理与稳定性)

微服务的高频问题，每题练到连续追问三层。

## Q1：gRPC 为什么比 HTTP/JSON 快？

Protobuf 二进制编码（小、快）+ HTTP/2 多路复用 + 头部压缩。

**追问：多路复用解决什么？** HTTP/1.1 的队头阻塞（一个连接同时只能处理一个请求）。

## Q2：微服务怎么拆分？

按业务领域边界，高内聚低耦合，每服务独立数据库。拆分过细的代价是分布式事务、调用链长、运维复杂。

**追问：同步还是异步通信？** 核心链路同步 RPC，可异步化（发短信）用消息队列。

## Q3：服务注册发现怎么做？

实例启动注册 + 心跳续期，调用方拉列表 + 负载均衡。下线先注销再停。

**追问：etcd 和 consul 区别？** etcd 强一致（Raft）带租约，consul 带健康检查。

## Q4：熔断、限流、降级区别？

限流控制进入量，熔断下游故障快速失败（Closed→Open→Half-Open），降级关非核心保核心。

**追问：为什么必须设超时？** 不设超时，慢服务会拖死所有调用方，级联雪崩。

## Q5：优雅上下线怎么做？

优雅停机：停新请求 → 处理在途 → 注销 → 退出（Go 用 signal.NotifyContext + Shutdown(ctx)）。优雅上线：预热完再注册接流量。

**追问：为什么需要预热？** 避免刚注册就被打满。

## Q6：超时重试有什么坑？

重试会重复执行副作用，所以重试必须配合幂等。

**追问：怎么保证幂等？** 唯一键、token、状态机。
