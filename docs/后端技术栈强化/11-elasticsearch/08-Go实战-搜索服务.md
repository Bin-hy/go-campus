> 属于 S11 Elasticsearch · 第八篇

前七篇讲的都是"ES 自己怎么工作"。回到你的岗位：业务服务大多是用 Go 写的，ES 只是被调用的一个外部依赖。这一篇用官方的 `go-elasticsearch/v8` 写一个能上线的搜索接入层：连接与超时、CRUD、**bulk 的逐条错误处理**、`search_after + PIT` 分页、聚合解析、**ES 挂了怎么降级**，最后是一个"索引重建 + 别名切换"的完整流程。

> 版本说明：本文基于 `github.com/elastic/go-elasticsearch/v8`。8.x 客户端可连 7.17+ 的集群；`olivere/elastic` 早已停止维护，**新项目不要再选它**（这是面试里"Go 怎么接 ES"的加分回答）。

## 一、客户端：选型与连接参数

```go
package search

import (
	"context"
	"crypto/tls"
	"fmt"
	"log"
	"net"
	"net/http"
	"strings"
	"time"

	elasticsearch "github.com/elastic/go-elasticsearch/v8"
)

func NewClient(addrs []string, user, pass string) (*elasticsearch.Client, error) {
	cfg := elasticsearch.Config{
		Addresses: addrs, // []string{"https://es-1:9200", "https://es-2:9200"}
		Username:  user,
		Password:  pass,
		// 传输层：连接池 + 超时，是 Go 接 ES 最容易忽略的一项
		Transport: &http.Transport{
			MaxIdleConns:          100,
			MaxIdleConnsPerHost:   20, // 默认 2，批量导入时必调大，否则连接复用不上
			IdleConnTimeout:       90 * time.Second,
			DialContext:           (&net.Dialer{Timeout: 2 * time.Second}).DialContext,
			TLSClientConfig:       &tls.Config{MinVersion: tls.VersionTLS12},
			TLSHandshakeTimeout:   3 * time.Second,
			ExpectContinueTimeout: 1 * time.Second,
		},
		// 只对 429/502/503/504 做有限重试，指数退避
		RetryOnStatus: []int{429, 502, 503, 504},
		MaxRetries:    3,
		RetryBackoff:  func(i int) time.Duration { return time.Duration(1<<i) * 100 * time.Millisecond },
	}
	return elasticsearch.NewClient(cfg)
}

// 启动自检：连不上就别让服务起来（或降级到"搜索不可用"）
func Ping(ctx context.Context, es *elasticsearch.Client) error {
	res, err := es.Info(es.Info.WithContext(ctx))
	if err != nil {
		return err
	}
	defer res.Body.Close()
	if res.IsError() {
		return fmt.Errorf("es info: %s", res.String())
	}
	return nil
}
```

四个工程要点：

1. **每个请求都传 `context.Context`**：所有 `esapi.XxxRequest` 都有 `.WithContext(ctx)`，超时由调用方控制，别让一个搜索把用户请求挂住；
2. **重试要有限**：`RetryOnStatus` 只放 429/5xx，`MaxRetries` 3 次；无限重试 = 重试风暴（第 7 篇的 429 场景）；
3. **`MaxIdleConnsPerHost` 默认只有 2**：批量导入或高 QPS 时连接建/拆会把 ES 的 CPU 打满，必须调大；
4. **连不上时的行为要想清楚**：是启动失败，还是"搜索降级、其他功能可用"。

## 二、建索引：mapping + 别名一步到位

```go
func CreateIndex(ctx context.Context, es *elasticsearch.Client, name string) error {
	// 注意：JSON 里的索引名用占位符替换
	mapping := `{
	  "settings": { "number_of_shards": 3, "number_of_replicas": 1 },
	  "mappings": {
	    "dynamic": "strict",
	    "properties": {
	      "sku":        { "type": "keyword" },
	      "title":      { "type": "text", "analyzer": "ik_max_word", "search_analyzer": "ik_smart",
	                      "fields": { "kw": { "type": "keyword", "ignore_above": 256 } } },
	      "price":      { "type": "scaled_float", "scaling_factor": 100 },
	      "status":     { "type": "keyword" },
	      "created_at": { "type": "date" }
	    }
	  },
	  "aliases": { "products": {} }   // 应用只认别名，物理索引可版本化
	}`
	res, err := es.Indices.Create(name, es.Indices.Create.WithContext(ctx),
		es.Indices.Create.WithBody(strings.NewReader(mapping)))
	if err != nil {
		return err
	}
	defer res.Body.Close()
	if res.IsError() && res.StatusCode != http.StatusBadRequest { // 400 可能是索引已存在
		return fmt.Errorf("create index %s: %s", name, res.String())
	}
	return nil
}
```

## 三、单条 CRUD 与乐观锁

```go
// 写入（指定 _id 保证幂等）
res, err := es.Index("products", bytes.NewReader(doc), "A1001",
	es.Index.WithContext(ctx), es.Index.WithRefresh("false"))
if err != nil { return err }
defer res.Body.Close()
if res.IsError() { return fmt.Errorf("index: %s", res.String()) }

// 部分更新（底层是读 _source → 改 → 删旧写新，别用于高频更新字段）
upd := `{"doc": {"price": 199, "updated_by": "ops"}}`
res, err = es.Update("products", "A1001", strings.NewReader(upd),
	es.Update.WithContext(ctx), es.Update.WithRefresh("false"))

// 乐观锁：带上你读到的 _seq_no/_primary_term，版本不符返回 409
res, err = es.Index("products", bytes.NewReader(doc), "A1001",
	es.Index.WithContext(ctx),
	es.Index.WithIfSeqNo(seqNo), es.Index.WithIfPrimaryTerm(term))
// 409 → version_conflict_engine_exception：重读最新版本再试，或直接返回"请刷新重试"
```

把 `_seq_no` / `_primary_term` 存进你的返回结构（或缓存），更新时带上，是后台管理系统的标准做法：**两个运营同时改同一商品，后保存的会收到 409，而不是静默覆盖**。

## 四、bulk：批量导入的正确姿势

`_bulk` 与普通 API 最大的区别：**HTTP 状态码 200 不代表全部成功**，每条结果要单独看 `items[i].error`。

```go
func BulkIndex(ctx context.Context, es *elasticsearch.Client, docs []Doc) (failed int, err error) {
	var buf bytes.Buffer
	for _, d := range docs {
		meta := map[string]any{"index": map[string]any{"_index": "products", "_id": d.SKU}}
		line, _ := json.Marshal(meta)
		buf.Write(line)
		buf.WriteByte('\n')
		body, _ := json.Marshal(d)
		buf.Write(body)
		buf.WriteByte('\n')
	}

	res, err := es.Bulk(bytes.NewReader(buf.Bytes()), es.Bulk.WithContext(ctx),
		es.Bulk.WithIndex("products"))
	if err != nil { return 0, err }
	defer res.Body.Close()
	if res.IsError() { return 0, fmt.Errorf("bulk http: %s", res.String()) }

	var br struct {
		Errors bool `json:"errors"`
		Items  []map[string]struct {
			Status int `json:"status"`
			Error  *struct {
				Type   string `json:"type"`
				Reason string `json:"reason"`
			} `json:"error"`
		} `json:"items"`
	}
	if err := json.NewDecoder(res.Body).Decode(&br); err != nil { return 0, err }
	if !br.Errors { return 0, nil }

	for i, item := range br.Items {
		for action, r := range item {
			if r.Error == nil { continue }
			failed++
			// 429：队列满 → 退避重试；400：mapping 冲突/字段类型错 → 修数据或改 mapping
			log.Printf("bulk item %d action=%s status=%d type=%s reason=%s", i, action, r.Status, r.Error.Type, r.Error.Reason)
		}
	}
	return failed, nil
}
```

生产建议直接用官方的批量助手 `esutil.BulkIndexer`：它内置 worker 池、按字节/条数/时间自动 flush，并给每条结果回调：

```go
import "github.com/elastic/go-elasticsearch/v8/esutil"

bi, err := esutil.NewBulkIndexer(esutil.BulkIndexerConfig{
	Index:         "products",
	Client:        es,
	NumWorkers:    4,               // 并发写，别超过 CPU 一半
	FlushBytes:    5 * 1024 * 1024, // 5MB 一批
	FlushInterval: time.Second,
	OnError:       func(ctx context.Context, err error) { log.Printf("bulk indexer: %v", err) },
})
if err != nil { return err }

for _, d := range docs {
	body, _ := json.Marshal(d)
	err := bi.Add(ctx, esutil.BulkIndexerItem{
		Action:     "index",
		DocumentID: d.SKU,
		Body:       bytes.NewReader(body),
		OnFailure: func(ctx context.Context, item esutil.BulkIndexerItem, res esutil.BulkIndexerResponseItem, err error) {
			// 单条失败：记日志 + 进补偿队列（不要吞掉）
		},
	})
	if err != nil { return err }
}
return bi.Close(ctx)
```

**bulk 的四个坑**：批太大（内存与单批失败回滚成本）、批太小（网络往返）、`refresh=true` 逐条刷新（慢十倍）、忽略 `items` 里的 error（数据悄悄丢了）。

## 五、搜索：DSL 构造与结果解析

```go
type SearchResult struct {
	Total int64
	Hits  []Product
	Took  int // 毫秒
}

func Search(ctx context.Context, es *elasticsearch.Client, kw string, page, size int) (*SearchResult, error) {
	dsl := map[string]any{
		"track_total_hits": true,
		"_source":          []string{"sku", "title", "price", "status"},
		"query": map[string]any{
			"bool": map[string]any{
				"must": map[string]any{
					"multi_match": map[string]any{
						"query":  kw,
						"fields": []string{"title^3", "title.kw"},
						"type":   "best_fields",
					},
				},
				"filter": []any{
					map[string]any{"term": map[string]any{"status": "on_sale"}},
				},
			},
		},
		"from": (page - 1) * size,
		"size": size,
		"sort": []any{map[string]any{"_score": "desc"}, map[string]any{"_id": "asc"}},
	}
	body, _ := json.Marshal(dsl)

	res, err := es.Search(es.Search.WithContext(ctx), es.Search.WithIndex("products"),
		es.Search.WithBody(bytes.NewReader(body)))
	if err != nil { return nil, err }
	defer res.Body.Close()
	if res.IsError() {
		return nil, fmt.Errorf("search: %s", res.String())
	}

	var out struct {
		Took int `json:"took"`
		Hits struct {
			Total struct{ Value int64 `json:"value"` } `json:"total"`
			Hits  []struct {
				Source Product `json:"_source"`
			} `json:"hits"`
		} `json:"hits"`
	}
	if err := json.NewDecoder(res.Body).Decode(&out); err != nil { return nil, err }

	r := &SearchResult{Total: out.Hits.Total.Value, Took: out.Took}
	for _, h := range out.Hits.Hits {
		r.Hits = append(r.Hits, h.Source)
	}
	return r, nil
}
```

注意：

- **`total` 是对象**（`{"value": 123, "relation": "eq"}`），直接 `int` 反序列化会报错；`relation=gte` 表示只统计了前 10000 条，要精确就得 `track_total_hits: true`（有成本）；
- **DSL 用 `map[string]any` 拼**最灵活；要类型安全可以用 8.x 的 `typedapi`（`esapi` 之外的第二套 API，结构体更直观，但版本耦合更紧）；
- **排序加唯一 tiebreaker**（`_id`）是为 `search_after` 留接口，也是稳定分页的前提。

## 六、深分页：search_after + PIT

```go
func SearchAll(ctx context.Context, es *elasticsearch.Client, index string, size int) error {
	pit, err := es.OpenPointInTime([]string{index}, "1m", es.OpenPointInTime.WithContext(ctx))
	if err != nil { return err }
	var p struct {
		ID string `json:"id"`
	}
	json.NewDecoder(pit.Body).Decode(&p)
	pit.Body.Close()
	defer func() { // PIT 不关会一直占资源
		es.ClosePointInTime(es.ClosePointInTime.WithBody(strings.NewReader(
			fmt.Sprintf(`{"id": %q}`, p.ID))))
	}()

	var after []any
	for {
		dsl := map[string]any{
			"size": size,
			"sort": []any{map[string]any{"created_at": "asc"}, map[string]any{"_id": "asc"}},
			"query": map[string]any{"match_all": map[string]any{}},
			"pit": map[string]any{"id": p.ID, "keep_alive": "1m"},
		}
		if after != nil {
			dsl["search_after"] = after
		}
		body, _ := json.Marshal(dsl)
		res, err := es.Search(es.Search.WithContext(ctx), es.Search.WithBody(bytes.NewReader(body)))
		if err != nil { return err }
		var page struct {
			Hits struct {
				Hits []struct {
					Sort   []any   `json:"sort"`
					Source Product `json:"_source"`
				} `json:"hits"`
			} `json:"hits"`
		}
		json.NewDecoder(res.Body).Decode(&page)
		res.Body.Close()
		if len(page.Hits.Hits) == 0 { break }
		for _, h := range page.Hits.Hits {
			process(h.Source)
		}
		after = page.Hits.Hits[len(page.Hits.Hits)-1].Sort
	}
	return nil
}
```

`search_after` 必须配合**唯一且稳定的排序**（`created_at + _id` 双键），否则边界文档会重复或丢失；PIT 保证翻页期间数据快照一致；**导出**用 `scroll`/PIT + `_doc` 排序（`_doc` 不排序、直接按段顺序读，最快）。

## 七、降级：ES 不能成为单点

搜索是"锦上添花"的功能，**ES 挂了业务不能全挂**：

```go
type Searcher struct {
	es    *elasticsearch.Client
	cache *redis.Client // 热门搜索词结果缓存
}

func (s *Searcher) Search(ctx context.Context, kw string) ([]Product, error) {
	if res, hit := s.cache.Get(ctx, "se:"+kw); hit {   // ① 缓存兜底
		return res, nil
	}
	ctx, cancel := context.WithTimeout(ctx, 300*time.Millisecond) // ② 短超时
	defer cancel()
	res, err := doSearch(ctx, s.es, kw)
	if err == nil {
		s.cache.Set(ctx, "se:"+kw, res, 30*time.Second)
		return res, nil
	}
	// ③ 降级：返回上次缓存 / 空结果 + 提示"搜索暂不可用"，而不是 500
	log.Printf("es search degraded: %v", err)
	return s.cache.GetStale(ctx, "se:"+kw)
}
```

降级矩阵（写进设计文档）：

| 故障 | 现象 | 降级策略 |
|------|------|---------|
| ES 整体不可用 | 连接超时/拒绝 | 读缓存/兜底列表；关闭搜索入口并提示；日志告警 |
| 429 背压 | bulk/search 被拒 | 客户端退避重试；批量导入暂停；非核心搜索限流 |
| 部分分片 red | 部分结果缺失 | 返回 `_shards.failed > 0` 的结果并标记；可接受（搜索本身容忍部分丢失） |
| 索引重建中 | 别名切换窗口 | 双写期间读老别名；切换后校验抽样 |

**注意**：搜索类接口对"部分失败"容忍度高（`_shards.failed`），但**同步写入不能容忍**——写 ES 失败要进重试队列，不能吞。

## 八、完整流程：索引重建 + 别名切换

```go
func Rebuild(ctx context.Context, es *elasticsearch.Client) error {
	const alias, oldIdx, newIdx = "products", "products_v1", "products_v2"

	if err := CreateIndex(ctx, es, newIdx); err != nil { return err }

	// 1) 全量回填（异步，用 _tasks 看进度）
	res, err := es.Reindex(strings.NewReader(fmt.Sprintf(
		`{"source":{"index":%q},"dest":{"index":%q}}`, oldIdx, newIdx)),
		es.Reindex.WithContext(ctx), es.Reindex.WithWaitForCompletion(false))
	if err != nil { return err }
	res.Body.Close()

	// 2) 等待 reindex 完成（轮询 _tasks）
	// 3) 增量双写：同步消费者同时写 oldIdx 与 newIdx
	// 4) 原子切换别名
	actions := fmt.Sprintf(
		`{"actions":[{"remove":{"index":%q,"alias":%q}},{"add":{"index":%q,"alias":%q}}]}`,
		oldIdx, alias, newIdx, alias)
	res, err = es.Indices.UpdateAliases(strings.NewReader(actions), es.Indices.UpdateAliases.WithContext(ctx))
	if err != nil { return err }
	defer res.Body.Close()
	if res.IsError() { return fmt.Errorf("swap alias: %s", res.String()) }

	// 5) 观察窗口后删除旧索引（可回滚：先保留 1~2 天）
	return nil
}
```

## 九、服务分层建议

```text
internal/search/
├── client.go      # 连接、超时、重试、健康检查
├── indexer.go     # bulk 写入 + 失败补偿队列（消费 MQ → ES）
├── query.go       # DSL 构造、结果解析、分页
├── degrade.go     # 缓存兜底、熔断开关、降级策略
└── reindex.go     # 全量重建 + 别名切换
```

面试时讲"我的项目怎么接 ES"，按这个结构讲：**连接要超时+有限重试、写入要幂等+逐条判错、查询要 filter 优先+深分页用 search_after、故障要缓存兜底+熔断开关、演进靠别名+reindex**——每一条都对应上面某一段代码。

::: warning 面试追问（3 层）
**Q1：为什么不用 `olivere/elastic`？**——它 2022 年后基本停止维护，且不支持 8.x 的很多新 API（如 PIT、typed client）。官方 `go-elasticsearch` 有完整的 `esapi`/`typedapi` 与 `esutil` 工具，版本兼容性有承诺。
**Q2：bulk 返回 200 就算成功了吗？**——不算。`_bulk` 是"逐条处理"，HTTP 200 只表示请求被受理；必须检查响应体的 `errors` 字段与每条 `items[i].error`，按错误类型（429 退避、400 数据/mapping 问题、409 版本冲突）分别处理。
**Q3：ES 客户端要不要重试？**——要，但只对幂等操作和可重试状态码（429/502/503/504）做有限次指数退避；写入必须幂等（用业务主键当 `_id`），否则重试会造成重复文档；查询重试要控制总超时，避免"重试放大延迟"。
:::

## 串起来

Go 接 ES 的骨架就五件事：**连接**（连接池 + 超时 + 有限重试）、**建索引**（mapping + 别名）、**写入**（幂等 `_id` + bulk 逐条判错 + `esutil.BulkIndexer`）、**查询**（`map` 拼 DSL、`filter` 优先、`search_after + PIT` 深分页）、**兜底**（缓存 + 熔断 + 降级）。最后用"新索引 + reindex + 别名原子切换"支撑演进。
