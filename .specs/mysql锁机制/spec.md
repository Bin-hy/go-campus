# MySQL 锁机制全解 · Spec

## 背景

`docs/后端技术栈强化/01-mysql/` 是 S1 MySQL 深入系列，现有深入篇共五篇：

1. 存储引擎与 B+ 树
2. 事务与 MVCC
3. 索引与 SQL 优化
4. 慢查询优化实战
5. 主从复制与高可用

其中《事务与 MVCC》只用两段带过了 next-key lock 和死锁，《存储引擎与 B+ 树》完全没提锁。读者读完能回答"MVCC 怎么让读不加锁"，却答不出：

- 一条 `UPDATE` 到底锁了哪些行、哪些间隙，为什么？
- 为什么 RR 下两个事务改不同的行也会互相阻塞？
- MDL 为什么会把整张表"锁死"、DDL 为什么能把线上打挂？
- 间隙锁、临键锁、插入意向锁、意向锁分别解决什么问题？
- 死锁是怎么被检测和回滚的，线上怎么排查？

锁是 MySQL 面试与线上排障的高频核心，当前系列缺少一篇系统讲解，形成明显缺口。

## 目标

- 新增一篇独立的锁机制长文，插入《事务与 MVCC》与《索引与 SQL 优化》之间，补齐 S1 深入篇的锁体系。
- 读者读完能**知其然亦知其所以然**：不仅知道 InnoDB 有哪些锁，还能解释每种锁为什么存在、由什么触发、锁范围怎么推导、出了死锁怎么定位。
- 与现有文章的导航、系列目录、侧边栏保持一致，不产生断链。

## 功能需求

- **F1 新增文章**：新建 `docs/后端技术栈强化/01-mysql/锁机制详解.md`，标题与开篇用场景化叙事（沿用本系列"先抛现象、再拆原理、末尾串起来"的风格）。

- **F3 Server 层锁**：讲解全局锁 FTWRL（用途、风险、为何 8.0 用 `--single-transaction` 替代）、表锁、MDL 元数据锁（自动加锁、读写互斥、长事务引发 DDL 阻塞雪崩）、AUTO-INC 锁（三种 `innodb_autoinc_lock_mode` 的取舍）。

- **F8 锁的可观测性**：给出查看锁等待与死锁的实用手段（`SHOW ENGINE INNODB STATUS`、`performance_schema.data_locks`、`performance_schema.data_lock_waits`、`sys.innodb_lock_waits`），并说明各自能看到什么。
