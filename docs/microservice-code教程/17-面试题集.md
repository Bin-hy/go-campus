# 17 面试题集：20 道高频追问

> 属于 Go 微服务实战教程 · 第 17 篇
> 上一篇：[16 实战验收：8 项清单](./16-实战验收8项清单)

每题按「考察点 → 追问链 → 答案要点」组织。建议先自己答，再对照；能连续答三层不卡壳，才算真正掌握。

## 一、gRPC

### 1. gRPC 为什么比 HTTP/JSON 快？

**考察点**：协议栈与编码。
**追问**：HTTP/2 解决了什么？Protobuf 一定更快吗？
**要点**：Protobuf 二进制、字段编号省去 key；HTTP/2 多路复用解决队头阻塞、头部压缩；强类型契约减少解析与联调成本。小 payload 时差异可能不大，优势在长连接与高并发。

### 2. 四种 RPC 分别什么场景？流的背压怎么做？

**考察点**：流式语义。
**追问**：`io.EOF` 含义？服务端流怎么取消？
**要点**：一元/服务端流/客户端流/双向流；背压依赖 HTTP/2 流控窗口 + `Send` 阻塞；`io.EOF` 表示发送方向正常结束；取消通过 ctx 传播，`Send/Recv` 返回 `Canceled`。

### 3. 拦截器顺序怎么定？流式拦截器有什么坑？

**考察点**：洋葱模型。
**追问**：为什么 recovery 要在最外层？
**要点**：进入左到右、返回右到左；recovery 最外才能兜住 panic；metrics 在 auth 外才能统计鉴权失败；流式要包装 `ServerStream` 才能替换 `Context()`。

### 4. deadline 和 timeout 的区别？跨服务怎么传？

**考察点**：超时预算。
**追问**：服务端为什么设 max deadline？
**要点**：timeout 是相对时长，deadline 是绝对时刻；gRPC 用 `grpc-timeout` 传递；每一跳共享同一 deadline，子调用剩余预算递减；服务端设上限防资源被占满。

### 5. 哪些 gRPC 错误可以重试？

**考察点**：错误分类。
**追问**：`Canceled` 为什么不能重试？
**要点**：`Unavailable/ResourceExhausted/Internal/Unknown` 视情况可重试；`DeadlineExceeded` 看剩余预算；`InvalidArgument/NotFound/Unauthenticated/PermissionDenied/Canceled` 不可重试。`Canceled` 是调用方主动放弃。

### 6. 健康检查怎么接 K8s？

**考察点**：探针与协议。
**追问**：`NOT_SERVING` 和断开连接的区别？
**要点**：注册标准 `grpc.health.v1.Health`；K8s 1.24+ 原生 `grpc` 探针；`NOT_SERVING` 主动告知，LB 可先摘流量；断开只能等客户端发现。

### 7. TLS 与 mTLS 的区别？证书怎么轮换？

**考察点**：传输安全。
**追问**：TLS 在哪终止？
**要点**：单向只验证服务端；mTLS 双向验证。轮换用 `GetCertificate` 动态加载 + cert-manager；入口网关终止外部 TLS，内部 mTLS 或服务网格。

### 8. Protobuf 哪些改动是兼容的？

**考察点**：线上契约。
**追问**：为什么编号不能复用？
**要点**：加字段、删除+reserved、rename（线兼容）、varint 家族互换、string↔bytes 兼容；改编号/跨线类型/重复性变更不兼容；未知字段必须保留。

## 二、服务治理

### 9. 为什么 gRPC 负载均衡在客户端做？

**考察点**：HTTP/2 长连接。
**追问**：代理 LB 什么时候用？
**要点**：单连接多路复用，连接均衡 ≠ 流量均衡；客户端选路少一跳、无代理单点、实例变更实时感知；入口流量用代理（Nginx/网关），内部用客户端 LB。

### 10. 服务注册发现怎么实现？注册中心挂了怎么办？

**考察点**：etcd/DNS。
**追问**：心跳与 TTL 怎么配合？
**要点**：etcd Lease（TTL）+ KeepAlive + Watch；宕机租约到期自动删除；客户端缓存最后一次列表 fail-static；K8s 用 Service/Headless DNS。

### 11. round-robin 和 P2C 怎么选？

**考察点**：选路策略。
**追问**：长尾请求怎么处理？
**要点**：同构、均匀用 round-robin；有慢实例/长尾用 P2C 或 least-request；P2C 抽两个选负载低的，避免羊群效应。

### 12. 为什么重试必须加 jitter？什么是重试风暴？

**考察点**：故障放大。
**追问**：重试预算怎么定？
**要点**：同步重试形成周期性尖峰；jitter 打散时间；重试预算限制重试占比（如 10%）；配合熔断快速失败。

### 13. 幂等键怎么设计？并发同 key 怎么处理？

**考察点**：业务幂等。
**追问**：失败要不要缓存？
**要点**：与业务动作一一对应、全局唯一、不可复用；原子占位（SETNX/唯一索引）+ singleflight 合并并发；只缓存成功结果，失败要释放。

### 14. 熔断器三态怎么转换？为什么 Half-Open 只放一个请求？

**考察点**：熔断。
**追问**：阈值怎么定？
**要点**：Closed→Open（连续失败阈值）→HalfOpen（冷却结束）→Closed/Open；单探针避免二次打挂；阈值结合下游恢复时间与流量。

### 15. 限流算法有哪些？令牌桶和漏桶的区别？

**考察点**：流量控制。
**追问**：分布式限流怎么做？
**要点**：固定窗口、滑动窗口、漏桶、令牌桶；令牌桶允许突发，漏桶恒定输出；分布式用 Redis + Lua 原子扣减。

### 16. 优雅停机为什么先摘流量再停服务？

**考察点**：发布可靠性。
**追问**：preStop 为什么要 sleep？
**要点**：Endpoint 摘除异步；先 readiness=false，再 sleep 收敛，再 `GracefulStop` 等在途；否则丢"刚转发"的请求。liveness 停机期间必须保持成功。

## 三、消息与一致性

### 17. Kafka 怎么保证不丢消息？

**考察点**：投递语义。
**追问**：exactly-once 能做到吗？
**要点**：生产端 `acks=all` + 幂等 producer + `min.insync.replicas`；消费端先处理后提交；流内 EOS 可做，跨外部副作用靠幂等表。

### 18. 重复消费怎么处理？死信队列怎么设计？

**考察点**：幂等消费。
**追问**：毒消息为什么不提交位点会卡住分区？
**要点**：业务幂等表（唯一键/SETNX）+ 三态；超过重试上限进死信并提交位点；死信记录原 offset、原因、trace id，提供重放工具。

### 19. Outbox 解决什么问题？为什么不能只靠 Kafka 事务？

**考察点**：双写一致性。
**追问**：relay 挂了怎么办？
**要点**：业务写库与事件写 outbox 同事务；relay 异步搬运；Kafka 事务管不到业务库；relay 重启后继续，重复由消费端幂等消化。

### 20. Saga 和 TCC / 2PC 的区别？补偿要注意什么？

**考察点**：分布式事务。
**追问**：悬挂、空补偿怎么防？
**要点**：Saga 本地事务 + 补偿（中间态可见）；TCC 预留资源；2PC 同步阻塞。补偿要幂等、可重入、可查询；状态机防悬挂与空补偿。

## 四、可观测与部署

### 21. trace_id 怎么跨服务传播？链路断了怎么排查？

**考察点**：分布式追踪。
**追问**：采样在哪做？
**要点**：W3C traceparent 放 metadata，客户端 Inject、服务端 Extract；断链常见于没透传 metadata、用了 `context.Background()`；入口采样并传播。

### 22. 为什么延迟用 Histogram？标签基数怎么控制？

**考察点**：指标设计。
**追问**：P99 为什么比平均值重要？
**要点**：Histogram 可聚合、可分位数；Summary 分位数不能合并；标签只放枚举维度；P99 反映长尾用户体验。

### 23. readiness 和 liveness 的区别？HPA 为什么不生效？

**考察点**：K8s 运维。
**追问**：滚动发布怎么保证 0 失败？
**要点**：readiness 摘流量，liveness 重启且不探下游；HPA 不生效常见于缺 requests、metrics-server 未装、容忍区间、min/max；滚动用 maxUnavailable=0 + readiness + preStop + PDB。

## 答题方法：三层递进

```mermaid
flowchart LR
    A[第一层：是什么] --> B[第二层：为什么]
    B --> C[第三层：出问题怎么办]
    C --> D[加分：我们线上怎么做的]
```

面试官真正想听的是第三层。比如问"重试"，不要只答"失败再试一次"，要答：

> 只对幂等且可恢复的错误重试，指数退避 + jitter 防重试风暴，重试前检查父 deadline 剩余预算，写接口用幂等键保证重复安全；下游持续失败时熔断快速失败。

## 串起来

这套题的答案都能在 `code/microservice/` 找到对应实现。面试前建议：**先讲结论，再讲机制，最后讲一次你亲手跑过的现象**（例如"停掉一个实例后，日志先 NOT_SERVING 再 GracefulStop，网关请求 0 失败"）。有代码、有现象、有取舍，比背定义更有说服力。
