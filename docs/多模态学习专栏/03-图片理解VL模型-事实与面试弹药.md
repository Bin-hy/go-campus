## 〇、先记住的三条"面试防翻车"原则

1. 架构图可以背，**参数量/dataset 规模/榜单分数一律不要背**，除非你当天查过 model card。
2. VL 模型的答案骨架永远是三段：**视觉编码器怎么出 token → 连接器怎么对齐 → LLM 怎么消费**。任何新模型都往这个骨架上挂。
3. 剪映/CapCut 场景的落点是 **OCR/字幕、镜头画面理解、grounding（"把这个人抠出来"）、视频时序**，而不是 MMMU 分数。回答时主动往业务靠。

## 一、知识分层清单

### 第 1 层：原理层（必须能推导，不能只背结论）

| 知识点 | 核心内容 | 面试可考形式 |
|---|---|---|
| 对比学习与对齐 | CLIP 用 image-text 对比损失（InfoNCE，softmax over batch）把图文拉到同一空间；SigLIP 换成 **sigmoid loss**，去掉 batch 内全局归一化，小 batch 更稳、可扩展 | "CLIP 和 SigLIP 的 loss 差在哪，为什么 SigLIP 更好训" |
| patchify | 图像切 `p×p` patch → 展平 → 线性投影为 token；token 数 `N = (H/p)·(W/p)` | "224×224、patch16、token 数多少" → 196 |
| 视觉 token 的经济学 | ViT 自注意力是 `O(N²)`，N 随分辨率**平方**增长：分辨率翻倍 → token ×4、注意力算力 ×16 | 见第三节 Q4 算术题 |
| 分辨率与 ViT 位置编码 | 固定位置编码无法外推；ViT 用插值；现代 VL 用 **2D-RoPE**（Qwen2-VL/2.5-VL）或 NaFlex（SigLIP2）原生支持变长宽比 | "训练 224、推理 1024 怎么处理位置编码" |
| 视觉表征的两条路线 | **CLIP/SigLIP 系（语义对齐，适合 VQA/检索）** vs **DINOv2 系（自监督、无文本对齐，dense feature/分割更强）** vs **EVA 系（CLIP 蒸馏 + MIM，容量大）** | "为什么多数 VLM 选 CLIP/SigLIP 而不是 DINOv2" |
| 连接器的本质 | 把 `N_v` 个视觉 token 映射到 LLM 词嵌入空间，并常常顺带**压缩数量**；LLM 侧全是"软 token" | "视觉 token 和文本 token 在 LLM 里地位一样吗" |
| 训练阶段语义 | 阶段一学"对齐"（视觉→语言空间），阶段二学"任务与指令"；冻结/解冻策略决定成本 | "为什么 LLaVA 只训 projector 也能 work" |
| 幻觉的根因 | 语言先验压过视觉证据 / 视觉 token 被稀释 / 训练数据里的共现偏置 / 自回归曝光偏差 | 见第一节"幻觉"专题 |

**关键算术模板（背这一条就够）**

```
视觉 token 数 = (H / p) × (W / p) / merge²
   Qwen 系: p=14, merge=2  → 每个 token 代表 28×28 像素
   CLIP-L/14: p=14, 无 merge → 每个 token 代表 14×14 像素

例:
  CLIP-L/14 @336      = (336/14)²        = 576 tokens
  Qwen 系  @1024×1024 = 1024×1024/784    ≈ 1338 tokens   [需核实取整方式]
  Qwen 系  @3840×2160 ≈ 8.29M/784        ≈ 10580 tokens  ← 4K 一帧就上万 token
```

### 第 2 层：架构层

#### 2.1 视觉编码器（必须能横向对比）

| 编码器 | 关键点 | 状态 |
|---|---|---|
| **ViT** | 原始 ViT 只做分类；被 VLM 借用时**丢掉 cls token 和最后的分类头**，取 patch 特征 | [已核] 常识级 |
| **CLIP-ViT** | L/14-336 是 LLaVA-1.5 的默认骨干；输出 576 token；末层特征常先过一层投影再进连接器 | [已核] |
| **SigLIP** | SoViT-400m/14 等，sigmoid loss；被 Idefics2、MiniCPM-V、Qwen3-VL 等采用 | [已核] |
| **SigLIP 2** | 2025 年 Google 发布，多语言 + 更好的定位/稠密特征；提供 **NaFlex**（native flexible resolution）变体，直接吃变长宽比 | [已核] [来源](https://google-research.github.io/big_vision/big_vision/configs/proj/image_text/README_siglip2.html) · [transformers 文档](https://huggingface.co/docs/transformers/model_doc/siglip2) |
| **DINOv2** | 自监督、无文本监督；强在 dense/patch 级任务（分割、深度、匹配），弱在开放词汇语义 | [已核] |
| **EVA / EVA-02** | 从 CLIP 蒸馏 + 掩码图像建模，参数大、特征强；CogVLM 系列用 EVA2-CLIP-E | [已核] |

**token 膨胀的三种主流缓解手段（务必能秒答）**
1. **Pixel shuffle / 2×2 merge**：Qwen2-VL 起，把 2×2 相邻 patch 在通道维拼起来再投影，token 直接 /4 → 28×28 像素一个 token。
2. **重采样压缩**：Q-Former 的 32 个 query、Perceiver Resampler、Idefics2 的 64 token 输出，把任意 N 压到固定 M。
3. **ViT 内窗口注意力 + 稀疏化**：Qwen2.5-VL 在 ViT 里做窗口注意力，把 `O(N²)` 降到近似线性，才敢吃高分辨率。

#### 2.2 连接器（Connector）——最高频的追问点

| 类型 | 机制 | 代表 | 取舍 |
|---|---|---|---|
| **线性投影** | 一层 `Linear(d_v → d_llm)` | LLaVA-1.0 | 最便宜，对齐能力弱 |
| **MLP（2 层）** | GELU + 两层 MLP | **LLaVA-1.5** | 便宜 + 够用，"一个 MLP 就够"的标准答案 |
| **Q-Former** | 32 个可学习 query 通过 cross-attention 从冻结 ViT 抽信息 | **BLIP-2** | 压缩比极高、可用冻结 LLM 训练；但 query 容量有限，细粒度/OCR 吃亏，且两阶段训练复杂 |
| **Perceiver Resampler** | 可学习 latent + cross-attn，输出固定长度 | Flamingo / Idefics2 | 同上，工程上更易并行 |
| **Native 行为（无独立连接器）** | ViT 直接与 LLM 维度对齐 + 轻量 merger，靠大规模原生多模态预训练打通 | Qwen2-VL/2.5-VL/3-VL、InternVL3 | 现代主流：牺牲一点参数效率换细粒度与统一训练 |

> 面试话术：**MLP 牺牲压缩比换保真度，Q-Former 牺牲保真度换压缩比和训练成本**。今天的主流是"少压缩 + 强预训练"，因为高分辨率/OCR/grounding 需求被业务逼出来了。

#### 2.3 代表 VLM 的架构要点（详细数字见第二节）

- **BLIP-2**：冻结 ViT + 冻结 LLM，只训 Q-Former；两阶段（表征学习 → 生成学习）[来源](https://github.com/macqueen09/paper_translate_reading/blob/main/md_file/BLIP-2_Bootstrapping_Language-Image_Pre-training.md)
- **LLaVA-1.5 / LLaVA-NeXT**：CLIP-ViT-L/14-336 + 2 层 MLP + Vicuna；两阶段（558K 对齐 → 665K 指令微调，具体规模 [需核实]）。NeXT 引入 **AnyRes**：把高分辨率图切成多个 tile，每 tile 独立过 ViT，再拼上缩略图，用换行 token 分隔。
- **Qwen-VL → Qwen2-VL → Qwen2.5-VL → Qwen3-VL**：Qwen-VL 用 cross-attention 式的 position-aware adapter；Qwen2-VL 起改为 **Naive Dynamic Resolution + M-RoPE**；Qwen2.5-VL 在 ViT 内加窗口注意力、引入**绝对时间编码**与动态 FPS 做视频；Qwen3-VL 为 2025 年最新一代（[技术报告 arXiv:2511.21631](https://huggingface.co/papers/2511.21631)，[模型卡](https://mintlify.wiki/QwenLM/Qwen3-VL/resources/model-cards)），定位 2D grounding/空间推理与长文档 OCR。
- **InternVL 2.5 / 3**：InternViT + MLP + InternLM/Qwen；InternVL3 主打**原生多模态预训练**（文本与多模态从预训练起就混合），并提出 V2PE（变长视觉位置编码）[官方博客](https://internvl.github.io/blog/2025-04-11-InternVL-3.0/)；InternVL3.5（2025-08）主打推理与效率 [博客](https://internvl.github.io/blog/2025-08-26-InternVL-3.5/)。
- **MiniCPM-V**：端侧强调，8B 级做到接近大模型的多模态表现，最新 4.5 版本基于 Qwen3-8B + SigLIP2 并引入 3D-Resampler 处理视频 [官方文档](https://raw.githubusercontent.com/OpenBMB/MiniCPM-V/refs/heads/main/docs/minicpm_v4dot5_en.md)（具体组件名与参数量 [需核实]）。
- **CogVLM / CogVLM2**：核心是 **Visual Expert**——在 LLM 的 attention 与 FFN 里为视觉 token 增加一组专属参数（不改 LLM 原有权重），等价于"给视觉开一条专用专家通路"。CogVLM2 基于 Llama3-8B [论文 arXiv:2408.16500](https://huggingface.co/buckets/huggingchat/papers-content/tree/2408/2408.16500.md)。
- **Idefics / Idefics2**：Flamingo 路线的开源化，Perceiver Resampler + 交叉注意力，跨图能力强。
- **Phi-3.5-Vision**：小参数量（约 4.2B 量级 [需核实]）+ 多帧拼接，微软小而强路线 [模型卡](https://huggingface.co/inference4j/phi-3.5-vision-instruct)。
- **Gemini / GPT-4o**：**闭源，架构未披露**。可直接讲的是：原生多模态（同一次预训练里混模态，非外挂编码器）、原生视频/音频、超长上下文视觉 token 预算。面试时明确说"内部结构未公开"，比编一个架构安全得多。Gemini 3 于 2025-11 发布 [来源](https://denmark.googleblog.com/2025/11/google-lancerer-gemini-3-lr-byg-og.html)。
- **GLM-4.5V**：2025 年智谱开源视觉推理模型，宣称刷新大量多模态榜单 [来源](https://www.163.com/dy/article/K6NKCQF105119734.html)。作为"国产开源 VLM 现状"的例子提到即可。

#### 2.4 训练三阶段（数据配方要点）

| 阶段 | 目标 | 数据配方要点 | 是否可跳过 |
|---|---|---|---|
| **① 对齐预训练** | 让视觉表征接入 LLM 词空间 | 大规模 **caption 对**（CC/LAION 类），只训连接器（常冻结 ViT 与 LLM）；分辨率低、epoch 少 | 不跳，但可极短 |
| **② 多任务预训练** | 学会"看图答题"的多种任务形式 | 混入 VQA / OCR / 检测框 / 图表 / 文档 / grounding，加入高质量合成数据；此阶段通常解冻 ViT（或部分层） | 现代模型基本必备 |
| **③ SFT / 指令微调** | 学会对话、格式、拒答 | 高质量**少而精**的指令数据（LLaVA 系 665K 量级 [需核实]），重格式与多样性；再叠加偏好优化（DPO/RLHF）降幻觉 | 不跳 |

**数据配方的三个面试要点**
- **比例决定能力**：OCR/文档数据给少了，公式识别和表格一定崩；grounding 数据给少了，坐标一定飘。
- **分辨率决定了训练数据的"上限"**：训练用低分辨率 caption，推理给 4K 图必然退化。
- **合成数据是当前 OCR/图表的主力**：用 HTML/LaTeX 渲染成图再配对，比爬真实文档便宜且干净。

#### 2.5 能力专题

| 能力 | 难点 | 典型做法 |
|---|---|---|
| **OCR / 文档理解（DocVQA）** | 小字号 + 密集文本 → 需要高分辨率 + 少压缩 | 高分辨率编码、动态分辨率、像素级对齐；代表模型普遍把 DocVQA/OCRBench 作为主战场 |
| **图表理解（ChartQA）** | 数值读取 + 算术，幻觉就错 | 高分辨率 + 结构化预训练数据；常接工具/代码执行 |
| **Grounding / 指代定位** | 输出坐标而非文本 | 用**归一化相对坐标**（`<|box_start|>` 类特殊 token）；Qwen 系列原生支持 2D 检测；M-RoPE 帮助空间对齐 |
| **计数** | 需要全局注意力，与压缩冲突 | 高分辨率 + 不要过度压缩 token |
| **空间关系** | "左/右/上/下"需要位置编码显式建模 | 2D/M-RoPE、绝对位置监督 |
| **多图输入** | 图间干扰、需要图分隔 token | `<image>` 占位 + 图像索引嵌入；Idefics 系强项 |
| **视频输入** | token 爆量（帧数 × 每帧 token） | 降 FPS + 空间池化 + 时间编码（Qwen2.5-VL 的绝对时间）+ 关键帧选择 |
| **GUI Agent** | 高分辨率长截图 + 精确点击坐标 | 视觉 grounding + 坐标回归；Qwen3-VL 明确主打 2D grounding/空间推理 |

#### 2.6 评测（要能说清"这个榜在测什么"）

| 榜单 | 测什么 | 坑 |
|---|---|---|
| **MMBench** | 综合能力，选择题 + CircularEval | 选择题可被语言先验蒙对 |
| **MMMU** | 大学学科级多模态推理 | 难，分数普遍低；对 prompt 极敏感 |
| **MME** | 感知 + 认知分项，是/否题 | 是/否题有偏置，"全答是"也能得分 |
| **POPE** | **幻觉**：polling 式问"图里有 X 吗"，看 yes/no 准确率 | 只测物体存在性，不测关系幻觉 |
| **HallusionBench** | 幻觉 + 视觉错觉，专测"看图说话是否被先验带跑" | 难度高，分数方差大 |
| **OCRBench** | 文本识别/文档/手写/KIE 综合 | 中文场景需额外看中文子集 |
| **DocVQA / ChartQA** | 文档/图表问答（多为 ANLS / relaxed accuracy） | ANLS 对 OCR 小错容忍，别直接和准确率混谈 |
| **MathVista** | 数学 + 视觉联合推理 | 依赖 CoT，结论波动大 |

参考工具：[EvalScope VLM 数据集列表](https://github.com/modelscope/evalscope/blob/8ade4b2d9ebf36e17583798b979d011a78030645/docs/zh/get_started/supported_dataset/vlm.md)

#### 2.7 幻觉：成因分类与缓解

**成因（面试分四类说）**
1. **语言先验主导**：LLM 太强，没看图也能答得像。
2. **视觉信息不足**：token 被压缩/分辨率不够 → 关键细节根本没进模型。
3. **数据共现偏置**：训练集里"厨房一定有微波炉"，模型就补出来。
4. **自回归曝光偏差**：一旦生成错 token，后续被自己的错误上下文带偏。

**缓解手段（按性价比排序）**
- 数据侧：加负样本（POPE 式构造）、加 OCR/细粒度数据、偏好优化（DPO）打幻觉样本。
- 架构侧：提高有效视觉 token 数、加强视觉-语言对齐模块、视觉对比解码（对比"有图/无图"两次 logits）。
- 推理侧：**先描述后回答**（先让模型输出图中观察再答）、CoT、self-check、要求引用图中证据（坐标/文字）。
- 评测侧：用 POPE + HallusionBench 做回归，别只看 MMBench。

参考综述：[Survey of Hallucinations in LVLMs](https://crad.ict.ac.cn/en/article/doi/10.7544/issn1000-1239.202440444)

### 第 3 层：工程层（这是 Go 工程师的相对优势区）

| 主题 | 要点 | M5 可行性 |
|---|---|---|
| **量化** | 权重：AWQ / GPTQ / bitsandbytes NF4 / **GGUF(Q4_K_M)** / **MLX 4bit**；激活：FP8（需 Hopper+）。视觉塔通常保留 FP16，LLM 部分量化即可 | ✅ 全部可做（除 FP8） |
| **推理引擎** | vLLM：`limit_mm_per_prompt`、`mm_processor_kwargs` 控图像数与分辨率上限，PagedAttention + prefix caching；SGLang：RadixAttention，多模态请求缓存友好 | ❌ **vLLM/SGLang 不支持 MPS**，Mac 上必须用 llama.cpp / MLX / transformers+MPS |
| **服务侧优化** | 图像预处理（resize/归一化）是 CPU 瓶颈 → 独立进程池；同图多请求做 **图像 embedding 缓存**（hash → vision feature）；系统 prompt 前缀缓存 | ✅ 可在 M5 上量测 |
| **token 预算** | 每张图的 `max_pixels` 直接决定 prefill 时间与 KV cache 占用；生产上按业务分级（缩略图 512 / OCR 2048+） | ✅ |
| **KV cache** | 视觉 token 是 KV cache 的主要膨胀源；长视频务必做帧级淘汰/摘要 | ✅ 概念可验证 |
| **预处理对齐** | 尺寸必须对齐到 `patch × merge`（Qwen 系 28）的倍数，否则被内部 resize，导致坐标偏移 | ✅ |

## 三、面试高频问题（10 题 + 答案要点）

**Q1. LLaVA 为什么一个 2 层 MLP 就够，不需要 Q-Former？**
① MLP 不做 token 压缩，视觉 token 一个不少地进 LLM，保真度高，对 OCR/细粒度任务友好。② 训练目标足够简单，配合冻结 ViT + 冻结 LLM 就能对齐，工程成本低。③ LLM 本身容量够大，能"自己学会"怎么读软 token，连接器不需要太聪明。④ 代价是序列变长、prefill 变贵；所以在 token 昂贵的长视频场景，Q-Former/Resampler 又有回归价值。⑤ 一句话结论：**MLP 用算力换保真，Q-Former 用保真换算力**。

**Q2. Q-Former 和 MLP 的取舍，什么时候选哪个？**
① Q-Former 用 32 个 query 从 ViT 抽信息，token 数固定且极少，能配冻结 LLM 训练，显存友好。② 但 query 数量是硬瓶颈：信息一旦没被 query 采到就永久丢失，细粒度文字/小目标吃亏。③ MLP 保留全部 patch token，代价是 N 个 token 全进 LLM 的 attention，成本 `O(N²)`。④ 今天主流选 MLP/merger，原因是业务（OCR、文档、grounding）逼着要保真，且 LLM 侧有 flash-attention 等工程手段摊薄成本。⑤ 选型判据：**信息密度高（文档/截图）→ 少压缩；信息冗余高（视频/长图）→ 多压缩**。

**Q3. 高分辨率图片怎么处理 token 爆炸？**
① 先算账：token 数随分辨率平方增长，4K 一帧可能上万 token。② 手段一：**结构压缩**——pixel shuffle / 2×2 merge 让一个 token 覆盖 28×28 像素，直接省 4 倍。③ 手段二：**动态分辨率**——按需 resize 到对齐 patch 的尺寸，而不是无脑放大到固定大分辨率。④ 手段三：**切块（AnyRes/tiling）**——切成若干 tile 独立编码，可并行、可只对相关 tile 精读。⑤ 手段四：**注意力稀疏化**——ViT 内部窗口注意力把 `O(N²)` 降到近线性，这是 Qwen2.5-VL 能开高分辨率的关键。⑥ 工程上还有 `max_pixels` 上限 + 业务分级策略。

**Q4. 算一下 ViT 的分辨率代价。**
① patch16：224→196 token，336→441，448→784，token 数 ∝ 面积。② 自注意力是 `O(N²)`：224→336 面积 2.25 倍，注意力算力约 5 倍。③ 全局算力近似：ViT-B/16@224 前向约 17.6 GFLOPs 量级，分辨率翻倍时线性部分 ×4、注意力部分 ×16，实际增长介于两者之间。④ 对 VLM 更致命的是 **LLM 侧**：视觉 token 全进自注意力，1 万 token 的 KV cache 直接吃掉几 GB。⑤ 结论：提升分辨率前先问"这一档分辨率对当前任务有没有收益"，用 token 预算表做分级。

**Q5. 怎么减少幻觉？**
① 先分因：语言先验太强 / 视觉证据不足 / 数据共现偏置 / 自回归误差累积。② 数据侧加负样本与偏见样本（POPE 式构造 + 偏好优化）。③ 架构侧提高有效视觉 token 密度、加强连接器对齐。④ 解码侧用"先观察再回答"、对比解码（对比有图/无图 logits）、self-check。⑤ 评测侧必须用 POPE/HallusionBench 做回归，只看 MMBench 会漏。⑥ 产品侧最有效的一招：**要求模型输出可核验的证据（引用图里的文字或坐标）**。

**Q6. 变长宽比和任意分辨率，位置编码怎么处理？**
① 固定 1D 位置编码无法外推，最早靠插值。② Qwen2-VL 起用 **M-RoPE**：把位置拆成时间/高度/宽度三个分量分别编码，天然表达 2D 空间与视频时间。③ Qwen2.5-VL 进一步用**绝对时间编码**，让模型理解真实时间尺度而非帧索引。④ SigLIP2 走 **NaFlex** 路线，编码器原生吃变长宽比。⑤ 好处是 grounding 坐标更准、任意长宽比不畸变；代价是 RoPE 实现更复杂、预填充更碎。

**Q7. OCR / 文档理解为什么特别难？**
① 文本是小目标、高频细节，token 压缩和低分辨率一动就丢。② 需要"字面识别"能力，而对比学习预训练偏向语义而非字形。③ 文档有版式（表格/多栏/公式），需要结构理解而非纯视觉。④ 训练数据贵：标注成本高，所以大量依赖 HTML/LaTeX 渲染合成。⑤ 工程上要放大分辨率 + 限制压缩比例，必要时切片分别 OCR 再汇总。

**Q8. Grounding（指代定位）是怎么输出坐标的？**
① 把框变成特殊 token 序列（如 `<box_start> x1 y1 x2 y2 <box_end>`），坐标**归一化到 0–1000**，与分辨率无关。② 归一化是关键：同一套权重能处理任意尺寸输入，推理时再乘回真实尺寸。③ 需要专门的 grounding 训练数据（RefCOCO 类 + 检测框）。④ M-RoPE/2D 位置建模对空间精度帮助很大。⑤ 生产坑：预处理 resize 不对齐 patch 倍数，坐标会系统性偏移——**必须按 28 的倍数对齐**。

**Q9. 评测榜怎么读？为什么不能只看一个分数？**
① MMBench 测综合但选择题可被语言先验蒙对；MME 大量是/否题，"全答是"也有分。② MMMU 测学科推理，难度高、对 prompt 敏感，绝对值低不代表模型差。③ POPE/HallusionBench 专测幻觉，和综合榜相关性低，必须单看。④ OCRBench/DocVQA/ChartQA 各管一段，ANLS 等指标对轻微 OCR 错误有容忍，别和 accuracy 混谈。⑤ 正确姿势：**按业务能力选榜 + 自己造 20–50 条真实样本做回归**，公开榜只用于筛候选。

**Q10. 多模态推理部署的瓶颈在哪？**
① 图像预处理（解码 + resize + 归一化）是 CPU 密集，常常比 GPU 推理还慢，要独立进程池。② 变长视觉 token 导致 batch 内长度差异大，需要 chunked prefill / padding 策略。③ KV cache 被视觉 token 撑爆，要限制 `limit_mm_per_prompt`。④ 同图重复请求做 embedding 缓存，系统 prompt 做 prefix caching，收益极大。⑤ 注意：**vLLM/SGLang 依赖 CUDA，Mac 上不可用**，本地只能走 llama.cpp/MLX；这一条在讲"本地验证 vs 生产部署"时是加分项。

## 四、Apple Silicon 最小实验（3 个）

**通用前提**
- M5 / 32GB 统一内存：GPU 与 CPU 共享内存，默认 wired limit 约为总内存的一部分，可用 `sudo sysctl iogpu.wired_limit_mb=24576` 放宽 [需核实具体默认值]。
- 路线选择：**MLX（mlx-vlm）** 最快且原生优化；**llama.cpp + GGUF** 兼容性最好；**transformers + MPS** 最好改代码、最容易踩坑。
- **不要尝试 vLLM/SGLang**（需要 CUDA/ROCm）。
- 下面所有时间/内存均为**量级估计，需实测**。

### 实验 1：跑通基线 + 测量 token/延迟/内存三元组（约 0.5 天）

**目标**：建立"分辨率 → token 数 → 延迟 → 内存"的手感，这是后面一切优化的基准。

**步骤思路**
1. 环境：`pip install mlx-vlm`（或 `pip install transformers accelerate` + MPS）。
2. 模型：`Qwen2.5-VL-3B-Instruct` 的 4bit MLX 版本（约 2GB 级权重 [需核实]）。备选 `Qwen3-VL` 最小档。
3. 写一个脚本，对同一张 1080p 截图分别设置 `max_pixels` 为 `512×28×28` / `1024×28×28` / `2048×28×28`，每次记录：① 实际送入的 image token 数（processor 返回值可读）② 首 token 延迟 ③ 解码速度 ④ 峰值内存（`mx.metal.get_peak_memory()` 或 `/usr/bin/time -l`）。
4. 任务：让模型 OCR 出截图里的所有文字，人工核对错误数。
5. 画一张表：三档分辨率 vs token 数 / 延迟 / 内存 / OCR 错误数。

**预期量级（需实测）**：3B 4bit 权重约 2GB；1080p 一图约 1.3k–2.5k 视觉 token（取决于档位）；prefill 秒级、解码 20–40 tok/s 量级；峰值内存 4–8GB。M5 上无需独显即可完成。

---

### 实验 2：Token 预算权衡 —— "OCR 准确率 vs 延迟" 曲线（约 1 天）

**目标**：得到你自己业务（字幕/小票/表格截图）的最优分辨率点，这是面试里最容易被追问的"你怎么定的参数"。

**步骤思路**
1. 自建 mini 数据集：20 张真实截图（10 张中文小票/表格 + 10 张 UI 截图），手工标注关键字段作为 ground truth（这一步别省，它是你唯一的评测依据）。
2. 写循环：分辨率档位 × 量化档位（4bit / 8bit / fp16）全组合跑一遍。
3. 指标：字段级准确率（不是字级）、平均延迟、峰值内存、显存/内存比。
4. 额外做一次**反直觉验证**：给一张 4K 图但强压 `max_pixels=512×28×28`，观察 OCR 是否断崖式下跌 —— 用来验证"token 预算 ≫ 分辨率数字"这个结论。
5. 产出：一张曲线图 + 一句结论（例如"在 3B 模型上，小票类 OCR 在 1024×28×28 档位达到收益拐点"）。

**预期量级（需实测）**：20 图 × 3 档 × 2 量化 ≈ 120 次推理，每次数秒到数十秒，半天内跑完；峰值内存 8–14GB（8bit 档更高）。

---

### 实验 3：能力边界实测 —— Grounding 坐标精度 + POPE 式幻觉（约 1 天）

**目标**：亲手摸到"模型什么时候在编"，并量化坐标偏移量，这是 VL 工程里最实用的直觉。

**步骤思路**
1. **Grounding**：拿 10 张含明显目标（人/文字/物体）的图，让模型输出 bbox（提示词用 `<box>` 或坐标格式），用 IoU 对照你手工框的 GT 算平均 IoU。
2. **坐标偏移验证**：同一张图分别用"对齐 28 倍数"和"不对齐"的预处理送入，对比 bbox 是否系统性偏移 —— 直接验证第三节 Q8 的工程坑。
3. **POPE 式幻觉**：对每张图构造 3 个问题（1 个真物体 + 1 个图中不存在的常见物体 + 1 个关系问题），统计 yes/no 准确率；重点看"物体不存在却答 yes"的比例。
4. **缓解对照**：对同一批题，分别用 (a) 直接问 (b) 先要求描述图中内容再回答，比较幻觉率变化 —— 验证"先观察后回答"是否真的有用。
5. 可选加分：用 `SigLIP2` 或 `CLIP` 做同一批图的 zero-shot 存在性打分，和 VLM 的 yes/no 对照，说明"专用判别模型 vs 生成式 VLM"在幻觉上的差别。

**预期量级（需实测）**：10 图 × 4 组提问 ≈ 40–80 次推理，秒级到十几秒一次，半天可完成；峰值内存与实验 1 同级。若改用 7B/8B 模型，内存翻倍、速度约减半，仍可在 32GB 上完成。
