# 架构师修炼栏目 Spec

## 背景

GoCampus 仓库已有 [后端技术栈强化](/后端技术栈强化/)（S1~S10：MySQL / Redis / Kafka / 微服务 / 高并发 / K8s / 分布式 / 对象存储 / Milvus）与[分布式系统面试详解](/第二阶段-知识详解/分布式系统面试详解)，它们解决的是「**组件原理是什么、理论是什么**」。

用户的真实诉求（原话）：面试考察**真实场景下的分布式架构、一致性设计与落地方案，以及不同 QPS 下架构设计的不同**；需要培养「真正的架构与落地经验」，覆盖 **Redis、MySQL、Kafka、etcd 主从同步**等真实场景处理；目标是**从单体架构成长为架构师**。

现有内容的缺口：

1. **没有量级坐标系**：读者知道 Redis 能缓存、Kafka 能削峰，但不知道「1 万 QPS 做什么、10 万做什么、100 万做什么」，容易出现「一上来就分库分表」的过度设计。
2. **没有落地参数**：原理篇讲「半同步更快不丢数据」，但不给 `rpl_semi_sync_master_timeout` 静默降级为异步这类真实坑，也不给 my.cnf / Redis / Kafka / etcd 的生产参数。
3. **没有故障边界**：没有系统性地回答「这个组件挂了 → 现象 → 降级 → 一致性怎么办 → 丢数据的窗口在哪」。
4. **没有可复现验证**：没有一套本机可跑的编排去亲手制造主从延迟、哨兵丢写、缓存雪崩打挂 DB、Kafka 丢消息、etcd 假死双写。
5. **`后端技术栈强化/index.md` 的 backlog 明确挂着**「分布式进阶（分库分表实战 / 分布式事务深入）——后续单独规划」，本栏目即该 backlog 的正式交付。

## 目标

- 新建独立顶层栏目 `docs/架构师修炼/`，主线是**QPS 六道坎驱动的架构演进**。
- 建立可复用的**架构师能力阶梯 A1~A5**（会用 → 懂原理 → **会算量** → **会选型** → **会演进与兜底**），并给出可验证的里程碑 M1~M6。
- 每篇统一结构：解决的问题 → 结论/对照表 → 机制 → **真实落地参数与 Go 代码** → **故障与一致性边界** → 面试追问链 → 自测清单。
- 配套 `code/architect/` 本机可跑的中间件编排（MySQL 主从、Redis 主从+哨兵、etcd 三节点、Kafka 单/三副本）与初始化脚本。
- 与既有内容严格互补并互链：原理查 S1/S2/S3/S8，本栏目只讲演进决策、落地参数、故障兜底。

## 功能需求

- **F1 方法论层**：`00 架构师思维与设计方法论`（五步法、量级估算公式、选型矩阵、白板模板）、`01 QPS 分级与架构演进地图`（六道坎量化标准 + 「同一件事在六个量级下的做法」总表 + 触发指标阈值表 + P0~P4 数据分级）。
- **F2 演进六阶段**：`02 单体架构的极限与分层`（四个天花板算量、Go 优化清单、压测找拐点）、`03 MySQL 主从与读写分离落地`（binlog 格式、GTID、半同步降级坑、并行复制、主从延迟治理、延迟感知路由）、`04 Redis 高可用与缓存体系落地`（PSYNC/backlog、哨兵 vs Cluster、防脑裂参数、五类缓存问题、多级缓存）、`05 Kafka 削峰与可靠投递落地`（acks/min.insync、ISR/HW/LEO、rebalance、积压处置）、`06 分库分表与在线迁移双写`（何时才拆、分片键、全局 ID、不停机迁移六步法）、`07 多活容灾与全球化架构`（单元化、冲突合并、RTO/RPO、成本）。
- **F3 一致性专题**：`08 缓存与 DB 一致性落地`、`09 分布式事务与最终一致落地`、`10 etcd 与 Raft 选主租约落地`（含 fencing token 防双写）、`11 幂等去重与 Exactly-Once`。
- **F4 稳定性工程**：`12 限流熔断降级与背压`、`13 容量规划压测与故障演练`、`14 备份恢复与故障复盘`（含 SLO/错误预算与复盘模板）。
- **F5 综合实战**：`15 案例：AI 剪辑任务平台架构`（贴合目标岗位）、`16 案例：Feed 与社区互动架构`、`17 面试：白板架构设计与追问链`、`18 实验手册：Go 落地实验`（15 个可复现实验 + 实验报告模板 + 简历写法）。
- **F6 代码层**：`code/architect/docker-compose.yml`（MySQL 主从、Redis 主从 + 三哨兵、etcd 三节点、Kafka 单节点 + cluster profile 三副本）、`conf/mysql/{master,replica}.cnf`、`conf/mysql/master-init.sql`、`conf/redis/sentinel.conf`、`scripts/init-replication.sh`、`README.md`。
- **F7 集成**：`docs/.vitepress/config.mts` 增加导航项与 `/架构师修炼/` 侧边栏（分组 A 方法论 / B 演进六阶段 / C 一致性 / D 稳定性 / E 实战 / 相关链接）；`docs/index.md` 增加 feature 卡与推荐顺序第 14 条；`docs/后端技术栈强化/index.md` 增加「下一步：架构师修炼」映射表并关闭 backlog；根 `README.md` 学习阶段表增加一行。

## 非功能需求

- **N1 风格一致**：中文、专业务实、先结论后机制、mermaid 图（含时序图与状态机）、对照表格、具体参数与数字；每篇必须含「故障与一致性边界」表与「面试追问链（带答案）」。
- **N2 零重复**：组件原理只做链接（`/后端技术栈强化/...`），不复制原理篇内容。
- **N3 不破坏既有站点**：不改动既有文档正文（仅允许在 `后端技术栈强化/index.md` 追加入口），不动既有侧边栏结构。
- **N4 可构建**：`npm run docs:build` 通过，无死链、无 mermaid 报错。
- **N5 编排可用**：`docker compose config` 校验通过；MySQL 主从可通过脚本一键初始化。

## 验收标准

1. `docs/架构师修炼/` 含 1 个首页 + 19 篇正文（00~18），文件名与 plan.md 一致。
2. 每篇正文含：导航块、「这篇解决什么问题」、≥2 个 mermaid 图、≥3 张表格、「故障与一致性边界」小节、「面试追问链」、「自测清单」。
3. 栏目内相对链接与站内绝对链接全部指向存在的文件（脚本校验通过）。
4. `npm run docs:build` 成功；`/架构师修炼/` 可在侧边栏完整导航。
5. `docker compose config -q` 与 `--profile cluster` 均通过。
